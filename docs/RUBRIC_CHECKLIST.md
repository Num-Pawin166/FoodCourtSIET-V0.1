## 1. UI/UX ตาม Material Design 3 + Usability Testing (3 คะแนน)

**เกณฑ์เต็ม:** ใช้ M3 สม่ำเสมอทั้งแอป **และ** มีรายงาน Usability Testing กับผู้ใช้ ≥ 5 คน

**ทำแล้ว**
- ทั้งแอปนักศึกษาและแอปร้านค้าใช้ `useMaterial3: true` และสีจาก `ColorScheme.fromSeed` ชุดเดียวกัน (`mobile/lib/theme.dart`, `vendor/lib/theme.dart`)
- คอมโพเนนต์ M3 ที่ใช้: `FilledButton`, `OutlinedButton`, `IconButton.filled`, `ChoiceChip`, `Badge`, `Switch`, `FloatingActionButton.extended`, `AlertDialog`, `ModalBottomSheet`, `SnackBar`, `showTimePicker`
- ฟอนต์ Prompt ฝังในแอป รองรับภาษาไทย
- แบบฟอร์มรายงานพร้อมใช้แล้ว: [USABILITY_TEST.md](USABILITY_TEST.md) มีโจทย์ 11 งาน (นักศึกษา T1–T7 และร้านค้า V1–V4), แบบสอบถาม SUS และวิธีคิดคะแนน

**ยังขาด**
- ❌ **ผลทดสอบกับผู้ใช้จริง ≥ 5 คน** ข้อนี้จะได้แค่ 1.5 จนกว่าจะทำ

**สิ่งที่ต้องทำ**
1. ติดตั้ง APK (ดาวน์โหลดจาก GitHub Actions → Artifacts) ให้ผู้ทดสอบ
2. ทดสอบ 5 คนขึ้นไป แนะนำนักศึกษา 4 คน + คนเล่นเป็นร้านค้า 1 คน
3. จับเวลา จดปัญหา และให้ตอบแบบสอบถาม SUS
4. กรอกผลลงใน USABILITY_TEST.md แล้วแก้ปัญหาที่ผู้ใช้เจอ 1–2 จุด (ใส่ลงสไลด์ในหัวข้อ "ก่อน/หลังแก้")

**สาธิตวันนำเสนอ:** เปิดแอปให้ดูหน้าหลัก แล้วแสดงตารางผล SUS และปัญหาที่แก้ไปแล้ว

## 2. REST API / Firebase Backend ≥ 2 บริการ (3 คะแนน)

**เกณฑ์เต็ม:** เชื่อมต่อได้จริงอย่างน้อย 2 บริการที่ทำหน้าที่ต่างกัน

**ทำแล้ว — มี 5 บริการ หน้าที่ไม่ซ้ำกัน**

| บริการ | หน้าที่ | ไฟล์หลัก |
|---|---|---|
| REST API ของเราเอง (Node.js + Express บน Render) | สั่งอาหาร คิว เมนู การชำระเงิน สิทธิ์ผู้ใช้ | `backend/src/` |
| Turso (libSQL cloud) | ฐานข้อมูลหลักของระบบ | `backend/src/db.js` |
| Google Gemini API | AI แนะนำเมนู | `backend/src/routes/ai.js` |
| Google Sign-In | ล็อกอินเฉพาะ @kmitl.ac.th | `backend/src/routes/auth.js`, `mobile/lib/google_auth.dart` |
| Firebase (Firestore + Auth) | รีวิวร้านแบบ real-time | `mobile/lib/reviews.dart` |

**สาธิตวันนำเสนอ:** สั่งอาหารจากแอปนักศึกษา → ออเดอร์เด้งในแอปร้านค้า (REST API + Turso) → ล็อกอินด้วย Google → ถาม AI → ส่งรีวิว

⚠️ **ระวัง:** Render แบบฟรีจะหลับถ้าไม่มีคนใช้ 15 นาที ให้เปิด https://foodcourt-siet.onrender.com ทิ้งไว้ก่อนเริ่มนำเสนอ 2–3 นาที

## 3. AI Feature (3 คะแนน)

**เกณฑ์เต็ม:** AI ทำงานครบ flow และเกี่ยวข้องกับวัตถุประสงค์ของแอป

**ทำแล้ว**
- **"ผู้ช่วย AI เลือกเมนู"**: นักศึกษาพิมพ์ เช่น "งบ 50 ไม่เผ็ด อยากได้เร็ว" แล้ว Gemini เลือกจาก**เมนูจริงของร้านที่เปิดอยู่** โดยเน้นร้านที่คิวน้อย
- **ครบ flow:** ถาม AI → ได้การ์ดเมนูพร้อมเหตุผล → กดการ์ดแล้วไปหน้าร้าน → ใส่ตะกร้า → สั่งได้ทันที
- ตรงกับเป้าหมายของแอป: ลดเวลาเลือกและกระจายคิวไปร้านที่ว่าง
- **ทำงานได้สม่ำเสมอ:**
  - ใช้ Gemini 3.5 Flash และสลับไปรุ่น Flash-Lite อัตโนมัติถ้ารุ่นแรกใช้ไม่ได้
  - ถ้า Gemini ล่มทั้งหมด จะใช้ตัวแนะนำแบบกฎแทน (กรองงบ ความเผ็ด ไม่กินหมู ฯลฯ)
  - แอปไม่ส่งข้อมูลส่วนตัวให้ AI และจำกัดไว้ 10 ครั้งต่อนาทีต่อคน
- จำประวัติแชตในเครื่อง (SQLite) และมีปุ่มล้างประวัติ

**สาธิตวันนำเสนอ:** แท็บ AI → พิมพ์ "งบ 50 ไม่เผ็ด" → กดเมนูที่แนะนำ → สั่ง

## 4. Local Database + Firestore (3 คะแนน)

**เกณฑ์เต็ม:** มีทั้ง Local Database และ Firestore ที่**บันทึกและอ่านข้อมูลได้จริง**

**ทำแล้ว — Local Database (SQLite ผ่าน sqflite)** · `mobile/lib/local_db.dart`

| ตาราง | ใช้ทำอะไร |
|---|---|
| `cart_items` + `kv` | ตะกร้าและหมายเหตุ ปิดแอปแล้วเปิดใหม่ยังอยู่ |
| `order_cache` | ออเดอร์ล่าสุด ดูเลขคิวได้แม้เน็ตหลุด (มีแถบ "ออฟไลน์") |
| `chat_messages` | ประวัติแชต AI |

เมื่อออกจากระบบ ข้อมูลในเครื่องถูกล้างทั้งหมด

**ทำแล้ว — Firestore** · `mobile/lib/reviews.dart`
- รีวิวร้าน 1–5 ดาวพร้อมความคิดเห็น เขียนได้จากแท็บประวัติ (ออเดอร์ที่รับอาหารแล้ว) และอ่านในหน้าร้านแบบ real-time
- Firebase project `foodcourt-siet` เชื่อมแล้ว (`google-services.json`, `firebase_options.dart`)
- มี security rules ใน `firestore/firestore.rules` และทดสอบแล้ว 15 เทสต์บน Firestore Emulator

**ยังขาด (ต้องทำก่อนนำเสนอ)**
1. ❌ Firebase Console → Authentication → Sign-in method → **Anonymous → Enable**
2. ❌ Firestore → Rules → วางเนื้อหา `firestore/firestore.rules` → **Publish** (test mode จะหมดอายุใน 30 วัน)
3. ❌ ลองบนมือถือจริง: สั่งอาหาร → ให้ร้านกด "ลูกค้ารับแล้ว" → รีวิว → เปิดหน้าร้านแล้วเห็นรีวิว และเห็นข้อมูลขึ้นใน Firebase Console

**สาธิตวันนำเสนอ**
- **Local DB:** ใส่ตะกร้า → ปิดแอปทิ้ง → เปิดใหม่ ตะกร้ายังอยู่ / เปิดโหมดเครื่องบิน → ยังเห็นเลขคิว
- **Firestore:** ส่งรีวิวจากมือถือเครื่องหนึ่ง → ขึ้นในหน้าร้านของอีกเครื่องทันที และเปิด Firebase Console ให้เห็น document ใหม่

**ประโยคสำหรับสไลด์:** "SQLite เก็บข้อมูลส่วนตัวที่ต้องใช้ได้แม้ออฟไลน์ · Firestore เก็บข้อมูลที่ทุกคนเห็นร่วมกันแบบ real-time · Turso เก็บข้อมูลหลัก (ออเดอร์ เงิน เมนู)"

## 6. GitHub Actions CI (3 คะแนน)

**เกณฑ์เต็ม:** Workflow รัน **Build และ Test** อัตโนมัติเมื่อ Push/PR และผ่าน (สีเขียว)

**ทำแล้ว** · `.github/workflows/ci.yml` รันทุกครั้งที่ push ขึ้น `main`, เปิด PR หรือกดรันเอง

| Job | ทำอะไร |
|---|---|
| Backend | เทสต์ + coverage ≥ 70% + เช็กว่าเซิร์ฟเวอร์เปิดได้ |
| Firestore rules | เทสต์ rules บน Emulator |
| Student app | analyze → test → coverage ≥ 70% → **build APK** |
| Vendor app | analyze → test → coverage ≥ 70% → **build APK** |

- รอบล่าสุดบน GitHub: ✅ เขียว (ก่อนเพิ่ม Firestore)
- มี badge CI ใน README และดาวน์โหลด APK ได้จาก Artifacts

**ยังต้องทำ:** commit + push งาน Firestore แล้วเช็กว่า**ทั้ง 4 job เขียว**

**สาธิตวันนำเสนอ:** เปิดแท็บ Actions ให้ดูรอบที่เขียว แล้วกดเข้าไปดูแต่ละ job และไฟล์ APK ที่ได้
